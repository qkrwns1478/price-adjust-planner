## 1. 도메인과 조건 충족 근거

| 선택 조건 | 근거 |
|---|---|
| 서로 다른 정보를 주는 외부 API 3종 이상 | 한국은행 ECOS 생산자물가지수(원재료 가격), 법제처 국가법령정보(법령 조문), 한국전력 계약종별 전력사용량(에너지 비용). 세 API 모두 실제 호출 성공 (3.1) |
| 출처와 이용 조건 기록 | [README.md](../README.md) '사용한 외부 API의 출처 및 이용 조건', [project_proposal.md](project_proposal.md) 1.3 |
| Tool 결과와 제약 조건을 비교해야 답할 수 있는 요청 | 2절 요청 4개. 지수 변동률과 약정 비율, 원재료 비중과 법정 기준(10%)을 비교 |
| 재계획이 의미를 가짐 | 요건 미달이면 다른 후보 지표(`next_candidate`), 다음 지수 발표 때 재조회(`recheck`), 연동이 아닌 조정 신청 경로(`alt_path`)로 대안을 찾음 |
| 저장, 조회, 수정, 삭제할 결과물 | 조정 협의 계획 (위탁기업, 품목, 원재료, 지표, 변동률, 요청 금액, 근거 조문, 협의 날짜와 시각, 상태) |
| 위험 도메인 면책 안내 | 법률 해석과 금전 판단이 걸린 위험 도메인. 모든 응답 끝에 면책 문구 표시 `F3011` |

## 2. 제약이 있는 요청 예시

| # | 요청 | 비교 | Tool 없이 LLM 만으로 답하면 틀리는 것 |
|---|---|---|---|
| 1 | "A사 납품 프레임이 개당 12만 원이고, 열연강판이 35%야. 약정서에는 5% 이상 변동하면 분기마다 조정한다고 돼 있어. 기준 시점은 작년 12월이야. 이번 분기에 요청할 수 있어?" | 변동률 15.29% ≥ 5%, 비중 35% ≥ 10% → 개당 6,422원 | 2025년 12월과 2026년 9월의 열연강판 지수를 알지 못해 변동률과 요청 금액을 지어낸다 |
| 2 | "알루미늄이 원가의 8%인데 연동 대상이야?" | 비중 8% < 법정 기준 10% → 대상 아님, 제22조의2 대안 경로 | 2026-09-29 시행 상생협력법의 조문 번호와 문구를 확인하지 못해 근거 조문이 틀리거나 없다 |
| 3 | "C사 납품 브래킷은 열연강판이 원가의 30%고, 약정 비율은 10%야. 기준 시점은 올해 3월이야. 이번 달에 조정 요청할 수 있어?" | 8.99% < 10% → 재계획, 요건 충족 지수 151.94 역산 | 최근 6개월 추세를 모르므로 요건 도달 시점과 미달 여부를 판단하지 못한다 |
| 4 | "우리 공장은 전기료가 납품대금의 12% 정도 돼. 전기료가 올라서 단가 조정을 요청할 수 있을까?" | 대구 산업용 평균판매단가 변동률과 약정 비율 비교 | 대구 산업용 전기요금의 월별 단가를 알지 못하며, 실제로는 하락(-11.05%)한 구간을 상승으로 답할 수 있다 |

## 3. 기획 검증 결과

### 3.1 외부 API 호출 확인

| API | 결과 |
|---|---|
| ECOS 품목 목록, 통계 조회 | 성공. 1,577행, 월간 최신 집계월 202609. 열연강판 202512 = 130.58, 202609 = 150.55 |
| 법제처 법령 검색, 본문 | 1차 `type=JSON` 실패(미신청 형식), XML만 성공 → JSON 추가 신청 후 성공. 상생협력법 조문 89개 |
| 한전 계약종별 전력사용량 | 성공. 대구 산업용 시군구 9곳, 최신 집계월 202609 |
| LLM (OpenAI) | 성공. Tool 명세(`catalog()`)를 넘기면 LLM이 `search_material_item → get_material_price_index → search_law_article`를 고름 |

상세: [verification_tools.md](verification/verification_tools.md) 3.1, [verification_agent.md](verification/verification_agent.md) 2절 2.7.

### 3.2 Tool 출력 구조 대조

실제 응답의 `ITEM_CODE`, `DATA_VALUE`, `조문번호`, `bill`, `powerUsage` 등이 Tool 출력 필드를 모두 채우는지 확인했습니다. 값이 비거나 집계 전 월이면 `NO_INDEX_VALUE`, 검색 결과가 없으면 `NO_DATA`로 실패 코드에 반영했습니다. 상세: [verification_tools.md](verification/verification_tools.md) 3.2, 3.3.

### 3.3 설계 시험과 설계 변경

| 시험에서 발견 | 설계 변경 |
|---|---|
| 법제처 응답의 `법령상세링크`에 OC가 들어 있음 | 법령명으로 공개 주소를 만들어 링크로 사용 `NF3002` |
| ECOS `sample` 키는 호출당 10행이라 품목 목록 수신에 4분 이상 걸림 | 품목 목록을 파일로 캐시하고 정식 키 사용 |
| 제안서 재계획 시나리오(형강 20%, 8%)가 실제로는 12.62% 로 요건 충족 | 재계획 대표 요청을 열연강판 30%, 10% 로 교체 (8.99% 미달) |
| 재조회 계획에서 추세를 얻으려면 상세 조회를 다시 불러야 함 | 첫 계획에서 `include_trend=true`로 한 번에 받고 재계획은 받은 추세를 재사용 |
| 지수 발표일을 날짜로 적으면 API로 확인하지 않은 값이 됨 | "2026년 10월 지수가 집계된 뒤"처럼 확인 가능한 사실로 표현 |
| 계획을 규칙만으로 만들면 Agent가 Tool 설명을 읽지 않음 | LLM이 Tool 명세로 계획 초안을 만들고 코드가 검증, 보정 |
| 계획 저장을 Tool(`save_adjustment_plan`)로 두면 사용자가 정한 값을 모델이 다룸 | 계획 관리 API로 분리 |
| 협의 예정일만 저장하면 시간 겹침을 판단할 수 없음 | 협의 날짜와 시작, 종료 시각 저장 |

상세: [verification_tools.md](verification/verification_tools.md) 3.4, [verification_agent.md](verification/verification_agent.md) 8절, [verification_plans.md](verification/verification_plans.md) 4절.

## 4. 기능적 요구사항

| 번호 | 분류 | 요구사항명 | 요구사항 상세 | 우선순위 | 상태 |
|---|---|---|---|---|---|
| `F3001` | Tool | Tool 명세 정의 및 등록 | Tool 4개의 이름, 설명(언제 쓰는지), 입출력 스키마를 정의하고 레지스트리에 등록한다. 외부 API 툴과 로컬 서버 API 툴을 `kind`로 구분하고, 모든 Tool은 `ok`, `data` 또는 `error(code, message)`로 답한다 | 필수 | ✅ |
| `F3002` | Tool | 후보 조회 Tool | `search_material_item`: 원재료 이름으로 ECOS 품목 코드 후보를 찾는다. 기준월이 없으면 최신 집계월을 쓰고, 미래 월이면 추정임을 밝힌다. 에너지경비는 `get_industrial_power_price`로 보충한다 | 필수 | ✅ |
| `F3003` | Tool | 상세정보 조회 Tool | `get_material_price_index`, `get_industrial_power_price`: 기준월과 현재월의 지수(단가)와 변동률을 확보한다. 값이 비어 있으면 `NO_INDEX_VALUE`로 판단하지 않고 둔다 | 필수 | ✅ |
| `F3004` | Tool | 보조 정보 검색 Tool | `search_law_article`: 법제처 API로 근거 조문의 번호, 제목, 발췌, 공개 링크를 찾는다. 결과가 없으면 `NO_DATA` | 필수 | ✅ |
| `F3005` | Agent | 사용자 요청 분석 | 의도(조정 계획, 사실 조회, 대상 판정, 계획 관리, 대화)를 분류하고 기준(위탁기업, 단가, 원재료, 기준 시점), 선호(지표, 지역), 제약(약정 비율, 주기) 조건을 추출한다. 뽑지 못한 조건은 비운다 | 필수 | ✅ |
| `F3006` | Agent | 작업 계획 수립 | Tool 명세를 받은 LLM이 Tool과 호출 순서를 고르고, 코드가 검증, 보정한다. Tool이 필요 없는 요청은 계획을 건너뛴다 | 필수 | ✅ |
| `F3007` | Agent | Tool 호출 및 결과 통합 | 후보 조회의 품목 코드를 상세 조회 입력으로 전달하고, 실패하면 사유를 기록하고 다음 단계로 진행한다 | 필수 | ✅ |
| `F3008` | Agent | 제약 적합성 판단 | 변동률을 약정 비율과, 원재료 비중을 법정 기준 10% 와 비교한다. 직전 조정 시점처럼 API로 확인할 수 없는 값은 지어내지 않고, 요건 충족 지수를 역산해 제시한다 | 필수 | ✅ |
| `F3009` | Agent | 재계획 | 충족 후보가 없으면 `next_candidate`, `recheck`, `alt_path` 순으로 재계획한다. 확보한 Tool 결과를 재사용하고, 상한 3회에 도달하면 사유와 함께 멈춘다 | 필수 | ✅ |
| `F3010` | Agent | 대화 맥락 유지 | 세션의 조건과 요약을 기억하고, 후속 요청에서 바뀐 조건만 갱신한다. Tool 원본 응답은 남기지 않는다 | 필수 | ✅ |
| `F3011` | Agent | 최종 응답 생성 | 결론, 판단 기준, 확인할 사항, 근거 조문, 근거 Tool 결과, 제외 사유, 면책 안내를 함께 제시한다 | 필수 | ✅ |
| `F3012` | 로깅 | 실행 이벤트 발행 | 노드 진입과 종료, Tool 요청, 응답, 소요 시간, LLM 판단과 이유를 `EventBus`로 발행한다. 발행은 구독자에 의존하지 않는다 | 필수 | ✅ |
| `F3013` | 로깅 | 실행 로그 저장 | 로깅 Agent가 이벤트를 구독해 세션 단위로 SQLite에 발생 순서대로 저장한다. 수집과 저장에 LLM을 쓰지 않는다 | 필수 | ✅ |
| `F3014` | 로깅 | 실행 로그 조회 및 삭제 | 세션 목록, 실행 순서 상세, 삭제 API를 제공한다. 수정 API는 두지 않고 DB 트리거로 수정을 막는다 | 필수 | ✅ |
| `F3015` | 계획 | 계획 저장 및 조회 | 조정 협의 계획을 협의 날짜, 시각, 생성 일시와 함께 저장하고 목록과 상세를 조회한다. 같은 날짜에 시간이 겹치거나 같은 위탁기업, 품목, 원재료로 진행 중인 계획이 있으면 저장하되 결과와 함께 알린다 | 필수 | ✅ |
| `F3016` | 계획 | 계획 수정 및 삭제 | 핵심 값과 상태(준비, 요청함, 합의, 거절)를 수정하고 삭제하며, 결과를 화면 목록에 바로 반영한다 | 필수 | ✅ |
| `F3017` | 서버 | 백엔드 API 서버 구현 | FastAPI로 대화(`/api/chat`), 계획 관리(`/api/plans`), 실행 로그(`/api/logs`), 설정 상태(`/api/status`) API를 제공한다 | 필수 | ✅ |
| `F3018` | UI | 프론트엔드 화면 구현 | HTML, CSS, JavaScript로 소개, 대화, 계획, 실행 로그 화면을 구현하고 API와 연동한다 | 필수 | ✅ |
| `F3019` | UI | 실행 과정 및 상태 표시 | 실행 이벤트 스트림으로 단계와 Tool 호출 이력을 순서대로 그리고, 재계획 지점, 처리 중 상태, Tool 실패, API 키 누락 안내를 표시한다 | 필수 | ✅ |
| `F3020` | 로깅 | 이상 징후 판단 | 로깅 Agent가 실행 로그로 반복 호출, 과도 재계획, 계획 외 호출, 고정 인자 변경을 규칙으로 판정한다. 근거가 없으면 판정 불가로 남기고, 이상 실행에만 LLM으로 원인을 진단한다 | 심화 | ✅ |
| `F3021` | Agent | Planner·Worker 구조 전환 | Planner가 고정 인자를 표시한 작업 목록을 만들고, Worker는 고칠 여지가 있는 실패에서만 LLM으로 재시도, 건너뜀, 계획 변경 요청을 판단한다. 로깅 Agent가 수행 결과를 검증하고 이상이면 Planner가 작업 목록을 다시 구성한다 | 심화 | ✅ |
| `F3022` | Tool | RAG 검색 Tool | 미적용. 판단 근거는 법제처 조문 원문과 한국은행 지수로 확보하며, 해설 문서 검색 결과가 공식 근거처럼 제시될 위험이 있다 | 심화 | ❌ |
| `F3023` | Tool | 캘린더 연동 Tool | 미적용. 협의 일정 겹침은 계획 저장 `F3015`에서 알리며, 일정은 조정 요건 판단에 영향을 주지 않는다 | 심화 | ❌ |

## 5. 비기능적 요구사항

| 번호 | 분류 | 요구사항명 | 요구사항 상세 | 상태 |
|---|---|---|---|---|
| `NF3001` | 보안 | API 키 관리 | 키 4종(`OPENAI_API_KEY`, `ECOS_OPEN_API`, `LAW_API_OC`, `KEP_CO_API`)은 `.env` 로만 관리하고 형상관리에서 제외한다 | ✅ |
| `NF3002` | 보안 | 화면 노출 제한 | 화면, 응답, 로그에 키 값과 예외 원문을 싣지 않는다. 키, 외부 API 오류는 일반 문구로 바꾼다 | ✅ |
| `NF3003` | 안정성 | Tool 실패 처리 | Tool은 예외를 던지지 않고 실패 코드로 답하며, Agent 실행이 실패해도 API는 오류 응답을 돌려준다 | ✅ |
| `NF3004` | 안정성 | 재계획 상한 | `MAX_REPLAN`(기본 3)에서 멈추고 그래프 `recursion_limit`도 이 값으로 정한다 | ✅ |
| `NF3005` | 성능 | 응답 시간 | 대표 요청을 30초 안에 처리한다 (실측 8 ~ 11초) | ✅ |
| `NF3006` | 구조 | 모듈 분리 | `frontend/`와 `backend/`를 분리하고 Agent(`app/agent/`), Tool(`app/tools/`) 코드를 파일로 나눈다 | ✅ |
| `NF3007` | 법 · 윤리 | 출처와 이용 조건 | 외부 API 3종의 출처, 이용 조건, 호출 한도를 README에 기록하고, 품목 목록 캐시로 호출을 줄인다 | ✅ |
