# 요청 분석 실패 표시 수정

- 작업일: 2026-11-20
- 범위: 실행 이력 화면의 실패 표시. GMS 429로 요청 분석 LLM이 응답하지 않는 상황에서 발견
- 결과: `unittest` 105/105 OK. 정적 파일 응답 헤더와 서버가 제공하는 `labels.js`, `app.css`, `trace.js` 내용을 `TestClient`로 확인.

## 1. 수정

| 발견 | 원인 | 수정 |
|---|---|---|
| 요청 분석이 실패해도 분석 단계와 실행 전체가 초록색으로 표시됨 | `analyze` 노드가 LLM 예외를 내부에서 처리하고 상태에 `error="ANALYZE_FAILED"`만 담음. 단계 종료(`node_end`), 요청 종료(`run_end`) 이벤트는 예외가 밖으로 나오지 않으면 항상 `ok=True`로 발행 | `graph.py`: `node_end.ok`를 단계 요약의 `error` 유무로, `run_end.ok`를 최종 상태의 `error` 유무로 정하고 `run_end`에 `error` 필드 추가 |
| 실패한 실행에 로깅 Agent 판정 배지가 "정상"으로 표시됨 | 판정 `F3020`의 검사 4개가 모두 Tool 호출 이력만 봄. 분석 실패는 Tool을 하나도 호출하지 않아 걸리는 항목이 없어 `normal`로 저장 | `reviewer.py`: 판정 값 `failed` 추가. 다른 이상이 없고 `run_end.ok`가 false이면 `failed`. 진단 LLM은 `anomaly`에만 부르므로 실패한 실행에는 부르지 않음. `logs.py` 응답 모델, `labels.js`("실패"), `app.css`(빨간 배지)에 반영 |
| 이전에 저장된 실패 실행도 "정상"으로 표시됨 | 저장된 판정이 `normal` | `trace.js`: 실행이 실패했는데 판정이 `normal`이면 `failed`로 표시 |
| 실패 시 "처리하지 못했습니다", "이 단계에서 오류가 발생했습니다.", "요청 분석 LLM 이 응답하지 않아…"가 한꺼번에 표시됨 | 실패 표시와 이유 설명이 각자 문구를 붙임. UI 설계 규칙(불필요한 설명 금지) 위반 | `trace.js`: 앞의 두 문구 제거. 실패는 배지, 빨간 테두리, 빨간 단계 표시로 전달하고 이유는 분석 단계의 판단 문구 한 줄만 남김. 실패한 실행에도 소요 시간 표시 |
| 실패한 실행의 응답 말풍선이 정상 응답과 같은 모양 | 응답 종류가 `notice`라 오류 스타일(`kind === "error"`)이 적용되지 않음 | `chat.js`: 실행이 실패했으면 말풍선에 오류 테두리 적용 |
| 배지가 영어 원문 "failed"로, 색상 없이 표시되고 제거한 "처리하지 못했습니다"가 남음 | 정적 파일에 캐시 정책이 없어 브라우저가 서버 확인 없이 이전 `labels.js`, `app.css`, `trace.js`를 재사용. 백엔드는 새 판정을 보내고 프론트는 이전 파일이 섞임 | `main.py`: 프론트 정적 파일에 `Cache-Control: no-cache`(`FrontendFiles`). 매 요청 재검증 |

## 2. 변경 파일

| 파일 | 내용 |
|---|---|
| `backend/app/agent/graph.py` | `node_end`, `run_end`의 `ok`를 상태의 `error`로 결정 |
| `backend/app/agent/reviewer.py` | `failed` 판정, `VERDICT_LABEL` |
| `backend/app/api/logs.py` | 판정 값에 `failed` 허용 |
| `backend/app/main.py` | `FrontendFiles`(no-cache 정적 파일) |
| `frontend/js/trace.js` | 실패 판정 표시, 중복 문구 제거, 실패 시 소요 시간 표시 |
| `frontend/js/chat.js` | 실패한 실행의 응답에 오류 스타일 |
| `frontend/js/labels.js`, `frontend/css/app.css` | `failed` 표기와 배지 스타일 |
| `backend/tests/test_logging.py` | `test_analyze_failure_is_not_reviewed_as_normal`: 분석기가 예외를 던지면 `analyze`, `run_end`가 `ok=false`이고 판정이 `failed` |

## 3. 확인 중 발견한 점

| 발견 | 처리 |
|---|---|
| 첫 수정(`ok` 값만 고침) 후에도 화면에 "정상"이 남음. 초록색의 출처가 단계 표시가 아니라 판정 배지였음 | 판정 자체에 `failed`를 추가. 프론트에서만 배지를 바꿔 치우던 중간 수정은 제거 |
| 프론트 수정이 화면에 반영되지 않아 일부 파일만 갱신된 상태로 보임 | 캐시 정책 추가. 이미 캐시된 브라우저는 한 번 강력 새로고침 필요 |
