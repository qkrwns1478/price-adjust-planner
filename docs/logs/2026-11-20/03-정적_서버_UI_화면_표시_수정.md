# 정적 서버 UI 화면 표시 수정

- 작업일: 2026-11-20
- 범위: Windows에서 Python 정적 서버로 프론트엔드를 열 때 헤더만 표시되는 문제 수정
- 결과: `frontend/serve.py`에서 `.js` MIME 형식을 `text/javascript`로 지정하고 프론트엔드 정적 서버 실행 방법을 README에 추가.

## 1. 문제 및 수정

| 문제 | 원인 | 수정 |
|---|---|---|
| 헤더 외 화면 요소가 표시되지 않음 | Windows MIME 설정에 따라 `.js`가 `text/plain`으로 전달되면 브라우저가 ES 모듈 실행을 거부하고, 각 화면의 `hidden` 속성이 해제되지 않음 | `frontend/serve.py`에서 MIME 형식을 지정한 뒤 `ThreadingHTTPServer`로 `frontend/`를 제공 |

## 2. 사용 방법

- 프로젝트 루트에서 `python frontend/serve.py 5500` 실행 후 `http://127.0.0.1:5500/` 접속.
- README에 Windows 기본 정적 서버에서 발생할 수 있는 MIME 문제와 실행 방법을 추가.

## 3. 추가 수정: 백엔드 응답 대기로 화면이 숨겨지는 문제

- `serve.py` 실행 후에도 헤더만 보인다는 제보를 받아 실행 중인 서버와 브라우저를 확인했다. 5500 서버의 `.js` 응답은 이미 `text/javascript`였다.
- 기존 `main.js`는 `await backendPageUrl()`이 끝난 뒤 화면의 `hidden` 속성을 해제했다. 브라우저에서 상태 API 응답을 지연시키자 모든 화면이 숨겨진 상태로 남는 증상을 재현했다.
- `main.js`에서 화면 초기화와 탭 이벤트 등록을 먼저 수행하고, 백엔드 확인은 비동기로 진행하도록 수정했다.
- `api.js`의 서버 주소 확인 요청에 3초 제한을 추가했다. 대화 스트림에는 적용하지 않는다.
- `index.html`의 소개 화면은 기본으로 표시하고, `serve.py`는 `Cache-Control: no-store`로 이전 스크립트와 MIME 응답의 캐시 재사용을 방지한다.

## 4. 확인 결과

- Chrome 브라우저 자동화로 수정 전 API 응답 지연 시 모든 화면이 숨겨지는 증상을 재현했다.
- 수정 후 같은 지연 상황에서 소개 화면 표시와 대화 탭 전환을 확인했다. 서버 주소 확인 제한 시간이 지난 뒤에도 탭을 사용할 수 있었다.
- 수정한 정적 서버를 5501 포트에서 실행하고 HTML, JavaScript, CSS의 200 응답과 MIME 형식, `Cache-Control: no-store`를 확인했다.
- 백엔드 연결을 차단한 상태에서 `#chat` 직접 접속과 소개·대화·계획·실행 로그 탭 표시를 확인했다. JavaScript 예외는 발생하지 않았다.
