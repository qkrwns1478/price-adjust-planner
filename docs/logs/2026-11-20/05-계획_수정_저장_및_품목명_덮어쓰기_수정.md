# 계획 수정 저장 오류와 후속 요청 품목명 덮어쓰기 수정

- 작업일: 2026-11-20
- 범위: 계획 화면의 수정 저장 실패와 후속 요청에서 품목명이 일반 명사로 바뀌는 오류
- 결과: 두 건 수정 후 브라우저와 `/api/chat`에서 재확인. 단위 테스트 106개 통과. `check_*.py`는 수정 후 다시 실행하지 않음.

## 1. 발견 및 수정

| 발견 | 원인 | 수정 |
|---|---|---|
| 계획 화면에서 「수정 저장」을 누르면 PATCH 요청 없이 `TypeError: Cannot read properties of undefined (reading 'trim')` 발생, 알림도 없음 | `changes()`의 `form.elements[name]`에서 `name`이 `item`이면 필드가 아니라 `HTMLFormControlsCollection.item()` 메서드가 반환됨 | `form.elements.namedItem(name)`으로 교체 |
| "원재료 비중을 10%로 바꿔서 다시 봐줘"라고 요청하면 품목명이 열연강판에서 "원재료"로 바뀜 (2회 재현) | 분석 결과가 `items_mode=replace`에 `name="원재료"`를 담았고, `merge_conditions`가 이를 새 품목으로 교체함 | 품목이 하나이고 새 품목명이 일반 명사(`GENERIC_ITEM_NAMES`)이면 직전 품목명을 유지하고 비중 등 나머지 값만 반영. 분석 프롬프트에 같은 규칙 추가 |

## 2. 변경 파일

| 파일 | 내용 |
|---|---|
| `frontend/js/plans.js` | `changes()`에서 `namedItem(name)` 사용 |
| `backend/app/agent/state.py` | `GENERIC_ITEM_NAMES` 추가, `merge_conditions`의 replace 분기에서 일반 명사 품목명이면 직전 품목명 유지 |
| `backend/app/agent/analyzer.py` | 일반 명사로 말하면 `items`에 그 말 그대로 적고 `items_mode`는 replace로 두는 규칙 추가 |
| `backend/tests/test_agent.py` | `test_generic_item_name_keeps_previous_item` 추가 |

## 3. 확인 중 발견한 점

| 발견 | 처리 |
|---|---|
| 첫 프롬프트 수정("일반 명사는 `items`에 적지 않고 비중만 바꾼다")으로는 품목명은 유지되지만 비중이 바뀌지 않음 (`changed: []`). 비중을 담을 곳이 없어졌기 때문 | 규칙을 "`items`에 `name`을 그 말 그대로, `share_pct`와 함께 적는다"로 바꾸고 병합 단계에서 품목명만 직전 값으로 유지 |
| `check_*.py`를 병렬로 실행하면 `data/scenarios`에 `1.json`만 남음. 단독 실행하면 `1.json` ~ `5.json`이 모두 생성됨 | 수정하지 않음. 하나씩 실행해야 함 |
