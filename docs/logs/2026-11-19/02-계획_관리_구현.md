# 계획 관리 구현 `F3015` ~ `F3016`

- 작업일: 2026-11-19
- 범위: 계획 관리 구현, 확인 항목
- 결과: `unittest` 81/81 OK, `check_plans.py` 11/11 PASS

## 1. 설계 결정

| 결정 | 근거 | 구현 |
|---|---|---|
| 계획 저장을 Tool이 아닌 API로 둔다 | 2.3 "관람 계획 저장처럼 사용자가 이미 정한 값을 다루는 작업은 Tool로 두지 않는다" | 제안서의 `save_adjustment_plan` Tool을 없애고 `/api/plans`로 대체한다 |
| 계산 값은 응답의 판단 결과에서 옮기고, 협의 일정은 사용자가 정한다 | `F3008` "외부 API로 확인할 수 없는 값은 임의로 정하지 않고" | 응답에 `plan_drafts`를 추가한다. `meeting_date`, `start_time`, `end_time`은 `null`로 둔다 |
| 날짜와 시작, 종료 시각을 저장한다 | ⑮ "대상 항목, 날짜, 시각 … 생성 일시", "같은 날짜에 시간이 겹치는 계획" | `meeting_date`, `start_time`, `end_time`, `created_at`, `updated_at`. 종료 ≤ 시작이면 422 |
| 겹침은 저장을 막지 않고 결과에 싣는다 | ⑮ "저장을 막지 않되, 그 사실을 저장 결과와 함께 알려야 한다" | `POST`, `PATCH`가 `{plan, overlaps, duplicates}`를 반환한다. 끝나는 시각에 시작하면 겹치지 않는다 |
| 진행 중인 같은 위탁기업, 품목, 원재료 계획도 막지 않고 알린다 | 제안서 3.7 중복 규칙을 ⑮ 와 같은 방식으로 맞춤 | `duplicates` (상태 `ready`, `requested`만) |
| 계획 저장소를 실행 로그와 같은 SQLite 파일, 다른 테이블에 둔다 | 1.2 데이터 영역 "계획 저장소" | `PlanStore(path)`, `create_app()`이 실행 로그 저장소 경로를 이어 쓴다 |

| 파일 | 내용 |

| `backend/app/storage/plan_store.py` | `PlanStore`: `plans` 테이블, `create`, `list`(협의 날짜, 시각 순), `get`, `update`(바꾼 값만), `delete`, `overlaps`, `duplicates` |
