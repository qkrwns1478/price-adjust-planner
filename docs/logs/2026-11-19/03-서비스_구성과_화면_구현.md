# 서비스 구성과 화면 구현 `F3017` ~ `F3019`

- 작업일: 2026-11-19
- 범위: 서비스 구성과 화면 구현, 확인 항목
- 결과: `unittest` 90/90 OK. 실제 LLM, 외부 API로 서버를 띄우고 headless Chrome으로 대화, 재계획, 계획 저장, 계획 관리, 실행 로그, 키 누락 화면을 확인했다. 브라우저 콘솔 오류 0건

## 1. 설계 결정

| 결정 | 근거 | 구현 |
|---|---|---|
| 대화 API를 두 경로로 둔다 | 17 "대화 요청 … API로 제공", 19 "처리 중 상태를 표시" | `POST /api/chat`는 응답을 한 번에, `POST /api/chat/stream`은 실행 이벤트를 발생 순서대로 보낸 뒤 마지막 줄에 응답을 싣는다 (NDJSON) |
| 스트림은 EventBus 구독으로 만든다 | `F3012` "이벤트 발행은 로깅 Agent의 구현에 의존하지 않아야 한다" | 요청마다 세션 id로 거른 구독을 붙였다 뗀다. 메인 Agent는 API를 알지 못한다 |
| 같은 세션의 요청은 순서대로 실행한다 | `F3010` 대화 맥락 유지 | 세션별 `threading.Lock` |
| 실행이 실패해도 오류 응답 형식으로 돌려준다 | `NF3002`, `NF3003` | 예외를 `kind: "error"`와 고정 문구로 바꾼다. 예외 원문은 싣지 않는다 |
| API 키는 설정 여부만 알린다 | 19 "API 키 누락 시 안내", `NF3002` | `GET /api/status`와 대화 응답의 `missing_keys`에 환경변수 이름만 싣는다 |
| Vue 없이 HTML, CSS, JavaScript 모듈로 화면을 만든다 | 18 "HTML, CSS, JavaScript 또는 Vue.js" | 빌드 없이 `frontend/`를 FastAPI가 `/`에서 제공한다. 다른 서버에서 열면 `window.API_BASE`로 주소를 지정한다 |
| 실행 과정은 이벤트로 그린다 | 19 "실행 단계와 Tool 호출 이력을 실행 순서대로", "재계획이 발생한 지점을 구분" | `trace.js`가 단계 → Tool 호출 순으로 그리고, `decision(kind=replan)` 자리에 재계획 구분선과 전략, 사유를 넣는다. 대화 화면(실시간)과 실행 로그 화면(저장본)이 같은 코드를 쓴다 |
| Tool 실패는 코드별 안내만 보여 준다 | 19 "Tool 실패 … 안내", `NF3002` | 실패 코드를 사람이 읽는 문장으로 바꾸고, 답변 상단에 실패 Tool 목록을 표시한다 |

## 3. 확인 중 고친 문제

| 문제 | 원인 | 수정 |
|---|---|---|
| 화면이 비어 있음 | Windows 레지스트리 설정 때문에 `.js`가 `text/plain`으로 제공되어 모듈 스크립트가 막힘 | `mimetypes.add_type`으로 형식을 지정하고 테스트에 MIME 확인 추가 |
| Tool 인자에 `true`가 표시됨 | `include_trend` 같은 불리언 인자까지 나열 | 불리언 인자는 표시하지 않음 |
| 재계획마다 같은 보정 문구가 반복됨 | 보정 내역이 계획 전체에 붙어 있음 | 최초 계획에서만 표시 |
| 키 안내가 있으면 대화 영역이 줄어듦 | 고정 높이 계산 | 페이지를 세로 flex로 바꿈 |
| 탭을 바꿀 때마다 "요청을 처리하지 못했습니다" 토스트 | VS Code Live Server(5500)에서 화면을 열면 API를 5500 으로 보내 404 | 화면을 연 서버의 `/api/status`를 한 번 확인하고, API가 없으면 `http://127.0.0.1:8000`으로 보냄 |
| Live Server로 연 화면에서 메시지를 보내면 아무것도 표시되지 않음 | 백엔드가 `data/planner.db`, 캐시를 쓰면 Live Server가 파일 변경으로 보고 페이지를 새로고침해 대화가 사라짐 | 로컬 `.vscode/settings.json`의 `liveServer.settings.ignoreFiles`에 `data/**`, `backend/**`, `*.db` 추가 (형상관리 제외) |

## 4. 추가 작업: 삭제 확인 모달

- 브라우저 `confirm`을 `<dialog>` 모달(`confirmDialog`)로 교체했다. 계획 삭제(`plans.js`), 실행 로그 삭제(`logs.js`)에 적용했다.
- 취소 버튼이 처음 포커스를 받고, Esc로 닫으면 취소로 처리한다.
- 삭제 버튼(`button.danger`)은 호버하면 빨간 배경에 흰 글씨로 바뀐다.

## 5. Live Server 새로고침 재수정

- `.vscode/settings.json`의 무시 설정은 실행 중인 Live Server에 적용되지 않아, 메시지를 보내면 `data/planner.db` 기록 때마다 페이지가 다시 새로고침됐다 (요청 1건에 3회).
- Live Server 설정에 기대지 않도록, 화면이 백엔드가 아닌 서버에서 열렸고 백엔드(`127.0.0.1:8000`)가 응답하면 `backendPageUrl()`로 백엔드가 제공하는 같은 화면(탭 포함)으로 옮긴다 (`api.js`, `main.js`).
- 확인: `localhost:5500/frontend/index.html#chat` → `127.0.0.1:8000/#chat`으로 이동, 메시지 전송 뒤 새로고침 0회, 사용자 메시지와 답변이 모두 표시됨.

## 6. 소개(랜딩) 탭

- 첫 탭으로 `소개`를 추가하고, 주소에 탭이 없으면 소개를 연다. 상단의 서비스 이름과 `대화 시작` 버튼은 각각 소개, 대화로 이동한다.
- 구성: 한 줄 제목과 시작 버튼 → 실제 계산 결과를 보여 주는 예시(요청 → 결과) → 처리 순서 4단계 → 근거 데이터 3종 → 재계획, 지어내지 않는 값, 공개되는 실행 과정 → 면책 문구. 설명 문장을 줄이고 배치로 전달한다.
- 변경: `frontend/index.html`, `frontend/css/app.css`, `frontend/js/main.js`
