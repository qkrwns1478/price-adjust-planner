## 3. 추가 확인

| 확인 항목 | 결과 |
|---|---|
| 초안의 계산 값이 응답의 판단 결과와 같고, 협의 날짜와 시각은 지어내지 않고 비워 두는지 | 변동률, 요청 금액 일치, `meeting_date: null` |
| 요건을 충족하지 못한 결과(재계획 요청)에는 초안이 없는지 | 열연강판 +8.99% < 10% → `plan_drafts: []` |
| "아까 그 계획 저장해 줘" 가 Tool 없이 계획 관리 안내로 이어지는지 | 의도 `manage`, `notice` 응답 |
| 같은 위탁기업, 품목, 원재료로 진행 중인 계획이 있으면 저장하되 알리는지 (단위 테스트) | `duplicates`에 기존 계획 |

## 4. 설계 변경

| 변경 전 (제안서) | 변경 후 | 이유 |
|---|---|---|
| `save_adjustment_plan` 로컬 서버 API Tool | 계획 관리 API (`/api/plans`) | 사용자가 이미 정한 값을 다루는 작업은 Tool로 두지 않는다 |
| 협의 예정일만 저장 | 협의 날짜와 시작, 종료 시각 저장 | `F3015`: 같은 날짜에 시간이 겹치는지 판단하려면 시각이 필요하다 |
| 같은 위탁기업, 품목 계획이 있으면 저장하지 않고 덮어쓸지 묻는다 | 저장하고 `duplicates`로 알린다 | 겹침과 같은 방식으로 저장을 막지 않고, 정리는 수정, 삭제로 한다 |
